# 1.0.8 发布隐私审查

范围：相对上次公开 1.0.5 的源码变化、待发布源码完整树、最终 DMG 解包后的应用、嵌入网关和 Node、扩展文件属性、发布提交历史及身份元数据。

## Standards

发现 1 项发布检查缺口，已修复：旧流程只检查源码和空接口预设，不能发现编译后的调试映射中残留的本机路径。

现在 `package_mac.sh` 在打包前去除主程序调试符号、重新签名，并执行 `scripts/audit_macos_bundle.py`；审查失败会阻断打包。该检查覆盖本机目录路径（含 UTF-16 和 JSON 转义）、非空预设、运行数据库/日志/签名文件、外部符号链接、常见凭据格式以及文件扩展属性。7 项独立合成数据回归测试通过。

## Spec

针对“上传的代码和安装包没有泄露本机隐私”，发现 1 项实际问题，已修复：初版 DMG 主程序内包含本机用户名和工作区路径的调试信息。剥离后本机路径匹配为 0，重新签名与重新生成的 DMG 再次通过完整扫描。

- 当前源码树未发现本机绝对目录、个人签名 Team ID、密钥或令牌。
- 发布包接口预设为空，未发现播放历史、收藏、账户数据库、缓存或本机配置文件。
- 应用使用 ad-hoc 签名，不包含个人开发者 Team ID 或签名证书。
- VLC 的私钥格式标记属于解析字符串常量，后接 NUL，不是完整私钥；Node 的宽泛访问密钥匹配来自长串嵌入数据，按完整令牌边界复核未命中。
- 三方依赖中剩余的绝对构建路径属于依赖自身的构建环境，不包含本机主目录。
- 使用单独的公开快照提交链发布，不推送含本地开发历史的工作分支；发布身份沿用已公开的 GitHub noreply 身份。

## 验证与限制

- 功能代码保持此前 193 项 macOS 测试通过的版本；本轮变更只涉及发布处理、隐私检查及文档。
- 逐个比对两种架构的非调试代码和数据 section，清理前后内容完全一致；最终应用的 Universal 2 架构、签名和 DMG 校验通过。
- 审查由当前代理完成。尝试启动的两个独立审查代理因额度限制未运行，未将其记作审查通过。
- 扫描结果代表上述规则和人工核对范围内未发现残留，不宣称能识别所有未知凭据格式。原始匹配值不写入日志、报告或发布说明。

结论：Standards 1 项检查缺口、Spec 1 项实际路径泄露，均已修复；发布前须对公开快照和上传资产再次核对。
