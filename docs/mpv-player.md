# mpv 播放器（macOS 1.0.8）

## 使用

设置 → 点播播放器或直播播放器 → mpv播放器。

- 视频解码选择“自动”或“硬解码”时，显式请求 Apple VideoToolbox；“软解码”关闭硬解。
- 控制栏显示 `hwdec-current` 返回的实际状态。片源编码或设备不支持硬解时允许回退软解，不把“已请求硬解”当成“正在硬解”。
- 支持暂停、进度跳转、倍速、音量、下一集、字幕选择和全屏。
- “字幕偏移”每次调节 0.5 秒，负值提前，正值延后。仅作用于独立字幕轨，不会改变压在视频画面内的字幕；切换视频时重置，全屏切换保留。
- 沿用应用的历史进度与播放实测记录。首次选择 mpv 不改变原有系统/VLC 设置的数值含义。

当前仅 macOS 构建加入 MPVKit；iOS 不显示不可用选项。

## 实现

固定依赖 MPVKit 1.0.0 的 LGPL 产品，通过 CAMetalLayer + gpu-next / MoltenVK 在应用内渲染，无需安装外部 mpv 命令行程序。依赖源码及二进制校验值由 Package.resolved 和固定版本的 Package.swift 记录。

libmpv 创建、命令、事件轮询、属性读取和销毁都由会话串行队列处理。销毁不阻塞主线程，视频层保留到视频输出退出。SwiftUI 内联/全屏共用控制器与画面，换源、请求头、直播模式或解码模式变化时创建新会话，通过标识丢弃旧回调。

1.0.8 build 7 在 macOS 目标中回移 mpv 官方 CoreAudio 初始化失败清理修复，避免音频设备变更时访问已释放的播放器对象。仅替换静态库中的 CoreAudio 驱动对象；固定依赖的内部 ABI、源文件校验值和升级移除步骤见 [回移说明](../Vendor/MPVCoreAudio/README.md)。

请求头使用 libmpv node 数组传递，保留 Cookie 中的逗号和反斜杠，拒绝换行/NUL 注入。不读取用户 mpv 配置或脚本，不记录媒体 URL/请求头日志。

## 验证

真实合成 H.264 双字幕视频覆盖：

- 实际推进播放时间，`hwdec-current == videotoolbox`（Apple M4）
- 自动选择中文、手动选择另一轨、关闭字幕
- 暂停、精确跳转、同一会话重绑和停止后忽略旧回调
- 强制软解 `hwdec-current == no`、从指定进度起播、结束回调
- 播放器选项持久化兼容、请求头处理和会话身份

真实播放测试针对本机 Apple Silicon；Intel 硬解和 iOS 尚未实机验证。MPVKit 的 Metal 路径是其维护的 mpv 补丁，升级依赖时需要重新执行真实渲染及全屏回归。

## build 7 闪退回归

- 本机原始报告：音频设备通知进入 `hotplug_cb → mp_msg → mp_msg_va` 后发生 `EXC_BAD_ACCESS`。
- 合成单声道 PCM 起播后退出，再创建并清理私有虚拟音频设备：旧代码崩溃，堆栈与报告一致；仅调整音频格式仍崩溃。
- 回移初始化失败清理补丁，并适配旧版失败路径，避免 AudioUnit 重复释放和监听计数下溢；相同测试通过。
- 8 项 mpv 测试通过：包含 10 次失败路径退出后的通知、5 次双声道真实播放及退出、播放中通知、超过 7 秒空闲关闭期限的暂停恢复，以及实际硬解、字幕、跳转和软解。
- macOS 全量 XCTest：195 项通过，0 失败。音频样本在临时目录生成并删除；不使用真实影片地址、Cookie 或用户配置。
- build 7 Universal 2 DMG 构建、签名、镜像校验及源码/应用包隐私审计通过，已替换本机应用并保留用户数据。启动后进程持续存活，主线程采样处于正常事件循环；窗口自动化未能读取界面，未将这一项计作界面验证通过。
- 此结果覆盖已复现的崩溃和上述操作序列，不等于已完成数小时连续播放、真实蓝牙设备切换或 Intel 实机验证。
