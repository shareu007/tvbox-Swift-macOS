# CatVod 资源检测与加载优化

日期：2026-10-15；1.1.0，构建 23。

## 问题与修复

- 普通 CatVod 返回播放 ID 时，旧检测直接标为需要播放确认，没有执行 Spider 解析。现在检测调用带 `verifyResource: true` 的播放解析，再抽检媒体；仅有剧集或播放 URL 不会被当作可用证据。
- 保留解析结果中的合法请求头。同源 HLS 子清单和片段继续使用这些头；跨域清空所有来源请求头，禁止 HTTPS 降级。抽检不读取浏览器 Cookie 或系统凭据，最多读取每个响应的 8 KiB。
- 网盘来源、分享链接、网盘线路标识和 CatVod 网盘描述符在 Gateway 父进程提前结束只读探测。不调用转存、下载地址或第三方网盘播放代码。网盘、网页解析及加密媒体仍标为需要实际播放确认。
- 剧集返回后立即可以打开详情，媒体探测在后台完成。每个资源的详情和播放抽检共享 12 秒预算，同时最多检查三个资源；超时保留剧集，停止或取消后丢弃迟到结果。
- CatVod 只读请求合并重复的在途请求，成功目录响应短期缓存 15 秒。缓存按会话、站点、初始化参数、动作、分页和筛选隔离，最多 64 项、2 MiB，仅存在进程内。失败或空列表不缓存；重新检测绕过旧详情缓存。播放解析响应不缓存，媒体仍逐次检测。

## 验证

- 播放 ID 回归最初失败：解析次数和媒体请求次数均为零；补齐后得到指定线路的媒体验证结果。
- 重复详情回归最初失败：同一个详情在来源队列中执行两次；修复后只执行一次。
- 不配合取消的慢探测最初阻塞详情，并超过等待预算；修复后先显示剧集，按预算结束，保留待确认状态，其他资源正常完成。
- 133 项相关 macOS 回归通过：资源检测、请求头隔离、停止和超时、原有首页恢复和协议适配、配置检测、字幕及 MPV 播放器。
- Gateway 全组 99 项通过；本机实际内置 Node 22 同样通过 99 项。覆盖实际 HTTP 入口、网盘只读边界、缓存失效、刷新、配置与筛选隔离、异常重试、内存上限和返回对象隔离。
- 合成样本使用 40 毫秒来源延迟：重复详情中位耗时从 42.462 毫秒降至 0.018 毫秒；六次打开的来源调用从六次降为一次。该数值用于验证缓存机制，不表示外部服务的实际响应速度。
- 新接口实际取得 96 个站点；三个普通影视来源的搜索、详情和播放地址解析通过。首次详情为 702/896/782 毫秒，重复读取均小于 1 毫秒。一个不含认证信息的公开媒体地址返回 HTTP 206，抽取 8192 字节并识别到媒体签名；另两个带查询信息的地址没有执行网络媒体抽检。

## 实际边界

抽检只证明当时某条线路首个媒体样本可读取，不能保证完整影片、后续剧集或账号鉴权都可播放。网盘真实账号播放和实际界面交互未作为本轮验收证据。首次加载仍受上游来源响应速度影响。

源码和安装包隐私审计、严格签名校验通过，构建 23 已替换正式安装版，完整内容与审计产物一致。旧安装版及本轮测试应用副本已删除，Spotlight 仅保留正式安装版。实际界面工具的本机控制通道启动失败，未完成真实点击验收。

真实入口、认证信息、播放 URL、Cookie 和影片响应不进入仓库、日志或测试样本。私有实测脚本已清理。此轮不发布 GitHub 或 DMG。
